# Contributing to NLP-refinement

Thank you for considering a contribution. This project accepts proposed
changes through GitHub Pull Requests (PRs).

## How to propose a change

1. Fork the repository to your own GitHub account.
2. Create a branch in that fork and make the smallest relevant change.
3. Add or update focused tests when the change alters executable behavior.
4. Open a Pull Request against this repository. Explain the problem, the
   intended behavior, and the verification you ran.
5. A project maintainer reviews the PR and decides whether to merge it.

Forking and opening a Pull Request does not require direct repository write
access. The project does not grant direct write access to external
contributors as part of ordinary contribution. Only a project maintainer may
merge a PR or publish a Python package release.

This project is licensed under Apache License 2.0. The canonical licence text
is in the root `LICENSE` file; the project copyright-holder notice is in the
root `NOTICE` file.

After that licence is in place, by submitting a PR for inclusion you confirm
that you have the right to submit the contribution and grant the project the
right to distribute that contribution under Apache License 2.0. Do not submit
material copied from a third party unless its licence is compatible and its
required notices are included.

This is an inbound-equals-outbound contribution rule, not a separate
Contributor License Agreement (CLA): the original rights holder retains its
copyright, while the project receives the rights needed to include and
distribute the accepted contribution under Apache License 2.0.

For a substantial contribution, an employer-owned contribution, or a
contribution whose origin or licence is unclear, a maintainer may pause review
and request written confirmation from the rights holder before merging. No
contributor receives a commit right, PyPI publication right, or project-owner
right merely by having a PR merged.

## Review boundaries

NLP-refinement is review-only. A contribution must not add target-worktree
repair, secret access, package installation during normal use, or a claim of
enforced host sandboxing without an approved design and evidence.
